# EMALTED — АСКТП підстанції 110/10 кВ

Демонстраційний інженерний вебпроєкт. Перша атестація з вебтехнологій, КПІ ім. Ігоря Сікорського.
Автор: Потяк М.В., група ТА-43.

**Сайт:** https://maksympotiak.github.io/emalted/

> EMALTED — вигаданий бренд. Компанія, підстанція, обладнання і всі значення на сайті є навчальними прикладами. Диспетчерська — симуляція в браузері без підключення до реального обладнання.

## Ідея

Усі три сторінки описують **один і той самий умовний об’єкт**: ПС 110/10 кВ (лінія Л-1, трансформатор Т1 25 МВА, секція шин 10 кВ, три приєднання). Числа узгоджені між собою. Сума сигналів за підсистемами дорівнює загальній кількості I/O, а потужність приєднань на «Огляді» збігається з симуляцією. Сім умов блокування зі сторінки «Рішення» — саме ті, які перевіряє диспетчерська перед командою «Увімкнути».

Візуальна мова — HMI за ISA-101: спокійний сірий інтерфейс, колір лише там, де він щось означає. Синій означає «під напругою», бурштиновий — попередження, червоний — аварію.

## Адаптивність

Mobile-first: базові стилі написані для телефона, медіазапити перебудовують розкладку для більших екранів.

| Точка зламу | Що змінюється |
|---|---|
| `< 24rem` (384px), малий телефон | компактні вкладки і відступи; таблиці-картки в один стовпчик; комірки стану диспетчерської на всю ширину |
| базова, телефон | один стовпчик; навігація — нижня панель вкладок; таблиці стають картками; зміст сторінки — стрічка; диспетчерська вертикально, шрифти схеми збільшені |
| `40rem` (640px) | підписи кнопок у шапці; галерея і підвал у 2 колонки; діаграма станів у рядок |
| `60rem` (960px) | меню в шапці; hero у дві колонки; таблиці знову таблиці; рівні архітектури в ряд; схема блокування горизонтально; диспетчерська у 2 колонки |
| `80rem` (1280px) | зміст «Рішень» — липка бічна панель; у диспетчерській колонка тривог праворуч, яка «липне» при прокрутці; етапи — горизонтальна шина |

Частина адаптивності працює без медіазапитів: `repeat(auto-fill, minmax(min(100%, …), 1fr))` і `clamp()` для шрифтів і відступів.

## CSS: Grid, Flexbox, медіазапити

**Grid:** hero, паспорт об’єкта, рівні архітектури, картки компонентів (`auto-fill`), показники, документ зі змістом (`14rem minmax(0, 1fr)`), рядки структурної схеми, I/O, схема блокування, зони безпеки, **диспетчерська (`grid-template-areas`, три різні розкладки)**, тренди, галерея-мозаїка, підвал.

**Flexbox:** шапка, сегментовані перемикачі, бейджі, вкладки, смуга стану диспетчерської (`flex-wrap`, на телефоні по 2 в ряд), заголовки панелей, рядки кнопок, дії діалогу, мобільна галерея зі `scroll-snap`.

**Інше:** `@layer`, CSS-змінні і дві теми, `:has()`, `attr()` у таблицях-картках, CSS counters, scroll-driven animation, View Transitions, `prefers-reduced-motion`, `<dialog>`, `<details>`.

Логіка без JS, на `:has()`: підсвітка протоколів на структурній схемі, логічне «І» блокування з 7 умов, фільтр журналу подій.

## JavaScript

| Файл | Функції |
|---|---|
| `app.js` | перемикач теми зі збереженням вибору; коливання вимірювань на мнемосхемі головної; «Режим ПНР» (рамки Grid/Flex з реальними колонками з `getComputedStyle`); поточний рік |
| `tabs.js` | вкладки за WAI-ARIA: клавіші ←/→/Home/End, `aria-selected`, прогресивне покращення |
| `scada.js` | `derive()` — що під напругою, струми і потужності; `conditions()` — умови блокувань; `raise / clear / ack` — життєвий цикл тривог; `selectCmd / execute` — команда «вибір → виконання» з таймаутом 10 с; `scenarios` — КЗ, несправність захисту, обрив каналу, EMERGENCY, випадкова подія; `tick()` — такт моделі з тепловою моделлю Т1 і автоматикою охолодження; `drawTrend()` — графіки на canvas з урахуванням DPR і теми |

## Перевірка

Усі сторінки автоматично перевірено на ширинах 320, 390, 768, 1024 і 1440 px: без помилок у консолі, без горизонтальної прокрутки, без битих зображень, посилань і якорів. Сценарії диспетчерської (КЗ, блокування, LOCAL, EMERGENCY, квитування, фільтр, клавіатура) пройдено автотестом.
